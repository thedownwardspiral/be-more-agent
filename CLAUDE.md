# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Be More Agent is a single-file Python application (`agent.py`) that turns a Raspberry Pi into a conversational AI agent. It uses wake word detection, local speech-to-text (whisper.cpp), the Anthropic API (Claude) for LLM intelligence, and local text-to-speech (Piper TTS). An internet connection is required for the Anthropic API.

## Running the Project

```bash
# First-time setup (installs uv + system deps, .venv with piper-tts + anthropic SDK,
# downloads a Piper voice into piper/, builds whisper.cpp)
chmod +x setup.sh
./setup.sh

# Configure your Anthropic API key
cp example.env .env && chmod 600 .env
# Edit .env and add your ANTHROPIC_API_KEY

# Run the agent (auto-targets DSI display via DISPLAY=:0)
uv run agent.py
```

There are no tests. Lint with `uvx ruff check agent.py` (config in `pyproject.toml`: line length 120, rules E4/E7/E9/F, E402 ignored for `agent.py`; the remaining findings are E701 one-liners) and syntax-check with `python3 -m py_compile agent.py`.

## Architecture

Everything lives in `agent.py` — a single ~1,850-line script with one main class:

**`BotGUI`** — The entire application. It's a tkinter GUI that also manages all background threads. Key sections (marked with comment banners in the file):

1. **Configuration & Constants** (top of file) — Before the GUI/audio imports, the preamble sets `DISPLAY`, computes `BASE_DIR = Path(__file__).resolve().parent` and `os.chdir`s there (so every relative path works from any launch directory), and sets up logging. That ordering is deliberate and is why ruff's E402 is ignored for `agent.py`. Then: `.env` is loaded from `BASE_DIR`; `load_config()` merges `config.json` over `DEFAULT_CONFIG` via `validate_config()` (see Configuration); `LLM_KWARGS` holds the optional `temperature` / `output_config={"effort": ...}` parameters shared by the chat stream and the warm-up call; `restrict_private_files()` chmods `.env`, `memory.json`, `agent.log` and its `LOG_BACKUP_COUNT` backups (`agent.log.1`–`.3`) to 0600 (called from `__main__`). Also defines the `BotStates` enum, the system prompt, the `TOOLS` schemas (and `TOOLS_WITHOUT_CAMERA`), `normalize_words()` (lowercase, hyphens/dashes to spaces, strip punctuation) with `CAMERA_TRIGGER_RE`, `MEMORY_WIPE_RE` and the (pre-normalized) `WHISPER_HALLUCINATIONS` set matched against its output, `normalize_for_tts()` (spells out `$` with an optional magnitude word, "$5 million" -> "5 million dollars", reads a dash between digits as " to ", turns other en/em dashes into ", ", spells out `%`, `°C/°F/°`, `&`, `+`, `=`, digit`/`digit, `#`digit, keeps apostrophes, then strips emoji/non-speech characters), the whisper transcript regexes, and `resolve_input_device()` / `choose_input_samplerate()`, which pick a microphone (via the `input_device` config key) and a verified sample rate. The Anthropic client is created lazily by `get_llm_client()` (first called from `warm_up_logic()`) with `timeout=60.0, max_retries=1`, so a dead network stalls a turn for about 2 minutes at most; a missing `ANTHROPIC_API_KEY` raises `MissingAPIKeyError`, which the warm-up shows on the ERROR face. An empty `ANTHROPIC_API_KEY=` counts as missing.

2. **GUI Class** — Fullscreen tkinter app (800x480, designed for the Pi's DSI touchscreen). The script sets `DISPLAY=:0` via `os.environ.setdefault` before importing tkinter, so it renders to the DSI display even when launched via SSH or systemd. Loads PNG animation sequences from `faces/[state]/` directories. Face state changes based on bot state (idle, listening, thinking, speaking, error, capturing, warmup).

   **UI queue:** worker threads never touch Tk. They call `self._ui(fn, *args)`, which puts a callable on `self.ui_queue`; `_process_ui_queue()` drains it on the Tk thread (FIFO), rescheduling itself after 30 ms when the pass did work and 100 ms when the queue was empty. `set_state()` and `append_to_text()` (also used for each streamed reply chunk) go through it. `set_state()` updates `self.current_state` synchronously on the calling thread (the worker reads it right after) and queues only the drawing. The only direct `master.after` calls are `update_animation()` and `_process_ui_queue()` rescheduling themselves on the Tk thread, plus the extra `quit` queued by the signal handler (which Python runs on the main thread). The open `BOT: ` line is tracked by `_bot_line_open` (main-loop thread only) and closed by `_end_bot_line()`.

3. **Tool Execution** (`execute_tool`) — Runs tools requested by Claude via native tool use. Three tools: `get_time`, `search_web` (DuckDuckGo), `capture_image` (Pi camera via `rpicam-still`). `capture_image` returns the photo as a base64 image block inside the `tool_result`, so Claude sees it with the full conversation history. The camera tool is offered only on turns whose user text matches `CAMERA_TRIGGER_RE` (built from `camera_trigger_words`); the tool list is chosen once per turn, and a call to a tool not offered that turn gets an `is_error` `tool_result`. Any exception from `execute_tool` is also returned to Claude as an `is_error` `tool_result` instead of aborting the turn (`execute_tool` returns `(content, is_error)`, so search and camera failures it catches itself are flagged `is_error` too; an empty search result is not an error). `rpicam-still` has a 20 s timeout.

4. **Core Logic** (`safe_main_execution`) — Main loop: detect wake word or PTT → record audio → transcribe → chat → speak. Two recording modes: adaptive silence detection and push-to-talk (Enter key). Enter toggles PTT on only while `detect_wake_word_or_ptt()` is waiting for a trigger (`awaiting_input` set, `current_state` IDLE); otherwise the press is refused, logged, and the status shows "Finishing..." for 1.5 s — so a press while a turn is still winding down (e.g. stalled after a spacebar interrupt) is never half-taken. Toggle OFF is always accepted. `handle_ptt_toggle` and the main loop share `ptt_lock`: right after a trigger the loop clears `awaiting_input`, and for a non-PTT trigger (wake word, CLI) also `recording_active`/`ptt_event`, so an Enter that landed with the wake word cannot arm PTT for the next turn. Spacebar (`handle_speaking_interrupt`) interrupts in SPEAKING, THINKING and CAPTURING; during a tool (search or camera) the loop runs no further tools, sends nothing back to Claude, and the end-of-turn cleanup deletes any photo. The wake-word listener (`_listen_loop`) uses cheap nearest-neighbor resampling, skips inference on near-silence, and retries once with fallback stream settings (blocksize 1024, high latency; still reading and resampling full 80 ms frames) before degrading to PTT.

   Recordings (`input.wav`) and camera photos live in a per-run `tempfile.mkdtemp()` directory (`self.tmp_dir`), marked live by an exclusive `flock` on `tmp_dir/.lock` held for the life of the process (released after the rmtree in `safe_exit`; `tmp_lock_guard` serializes the fd between `_lock_tmp_dir` and `safe_exit`, and `_lock_tmp_dir` does nothing once exiting). The lock is taken immediately after each `mkdtemp`. `_sweep_stale_tmp_dirs()` first removes this user's `be-more-agent-*` dirs whose `.lock` is missing or not locked, so a running instance's dir is skipped. `_ensure_tmp_dir()` recreates the dir (`os.mkdir` 0700) and its lock on demand before `input.wav` or a photo is written, since systemd-tmpfiles ages out `/tmp` entries idle for 10 days; if the name now belongs to another user or is not a directory it switches to a fresh `mkdtemp` dir (callers build file paths after the call), and it raises `OSError` once `safe_exit` has started; a failed `input.wav` write is logged and treated as "Heard nothing": the recording is deleted right after transcription, the photo after the turn (through the UI queue, after the overlay that uses it), and the directory at exit. Audio is clipped to ±1.0 before int16 conversion. `whisper-cli` runs with a 90 s timeout and a return-code check; every segment line is joined, and `_is_speech()` drops non-speech annotations and known silence hallucinations. If the warm-up call fails, the agent shows the ERROR face ("Can't reach Claude"), plays an error sound, skips the greeting, and still starts the main loop; the message is kept in `self.startup_error`, shown in the idle status ("Waiting... (...)") and in place of "Brain Freeze!" on a failed turn, and cleared once a turn gets a response. Each loop iteration has its own `try/except`: an unexpected error logs a traceback, shows "Something went wrong" for 2 s and keeps listening; the outer handler ("Fatal Error") only covers startup. SIGTERM/SIGINT run `safe_exit()` (save memory, stop audio, remove the temp dir, quit Tk). Memory is saved after every completed turn by `save_chat_history()`: under `memory_lock`, write `memory.json.tmp` with mode 0600, fsync, then `os.replace`. It keeps the system entry plus the last 10 conversation messages; `load_chat_history()` validates the file with `is_valid_memory()` (system entry first and only first, then `user`/`assistant` entries with non-empty string content) and starts fresh if it is malformed. With `chat_memory: false`, memory.json is never read or written, except that the memory wipe deletes a leftover one. The memory wipe fires only when the whole normalized utterance is "forget everything" or "reset (your) memory", optionally preceded by short lead-ins (ok/okay/hey/hi/um/uh/so/please/bmo/jarvis/robot, so the wake word is fine) and followed by "please" or "now"; "don't forget everything" still does nothing. The system prompt tells Claude it cannot erase its own memory and to point the user at "forget everything".

5. **Chat & Respond** (`chat_and_respond`) — Streams the response via the Anthropic Messages API with the turn's tool list and `**LLM_KWARGS`. History comes from `_history_messages()` (last `max_history_messages`, starting at a user message). When the stream ends with `stop_reason == "tool_use"`, it executes the requested tools, appends the assistant content and `tool_result` blocks to the messages, and loops so Claude can use the results in context. At most `MAX_TOOL_ROUNDS` (5) rounds run tools; one more round is then sent with `tool_choice={"type": "none"}` (`tools=` stays, since the API rejects `tool_use`/`tool_result` blocks in messages when no tools are defined) so Claude must answer in text, and if that still yields no text the bot says "I couldn't finish that one." and logs a warning. Streamed text is buffered and flushed to TTS up to the last sentence end in the buffer (`last_sentence_end()`: `TTS_SENTENCE_END_RE` punctuation, including `…` and closing quotes, followed by whitespace; stream deltas rarely end exactly on punctuation, so the rest stays buffered) once that part meets a minimum length, preventing choppy playback of short fragments. A period after a common abbreviation, a single letter or dotted initials ("St.", "p.m.", "U.S."), or a 1-2 digit list number ("1.") is not a sentence end (`TTS_ABBREVIATION_RE`), and the end of the buffer never is ("3." may continue as "3.14"). The first chunk of a turn, and the first chunk after each tool round, only needs `TTS_FIRST_SENTENCE_MIN_LENGTH` (default 20 chars) so the bot starts talking quickly; after that, chunks need `TTS_MIN_SENTENCE_LENGTH` (default 80 chars). Text left in the buffer at the end of each round is flushed regardless of length, so short replies like "Sure!" are still spoken.

**Key threading model:** The main loop runs in a daemon thread off the tkinter main thread. TTS has its own worker thread with a queue. At most one thinking-sound thread runs at a time (`_start_thinking_sound`), and it never plays while TTS is speaking or has speech queued; a clip is cut within 50 ms once `thinking_sound_active` clears or speech starts. The recorders join that thread (≤1 s) before their own `sd.stop()`, since stopping another thread's playback crashes PortAudio. Worker threads reach the GUI only through `self.ui_queue` (see the UI queue above). State coordination uses `threading.Event` objects; `memory_lock` serializes memory saves (main loop vs. `safe_exit` on the Tk thread).

## LLM Integration

The agent uses the **Anthropic API** (Claude) for all LLM tasks. The `anthropic` Python SDK communicates directly with Claude's Messages API — no local inference server is needed.

- **API Key**: Read from `ANTHROPIC_API_KEY` in `BASE_DIR/.env` (loaded via `python-dotenv`)
- **Model**: Defaults to `claude-haiku-5-5` (Claude Haiku 5.5). Override via `ANTHROPIC_MODEL` env var or `text_model` in `config.json`
- **Streaming**: Uses `client.messages.stream()` for real-time token delivery during conversation
- **Optional parameters**: `temperature` (default null) and `effort` (default `"low"`, sent as `output_config={"effort": ...}`) go into `LLM_KWARGS`; a null value omits the parameter. Claude 5.x models reject a non-default temperature. The chat stream's `max_tokens` is `MAX_RESPONSE_TOKENS`: 4096 when `effort` is set or `temperature` is null (the default; thinking is on by default and thinking tokens count toward the cap), else 1024. The warm-up call uses the same kwargs (`max_tokens=32`), so a mismatch fails at startup
- **Tool use**: Native Anthropic tool use (`tools=` parameter) — no prompt-engineered JSON protocol or output sniffing
- **Vision**: The `capture_image` tool returns the camera photo as a base64 image block inside the `tool_result`, so vision requests keep the full conversation history

## External Tool Chain (not in repo, installed by setup.sh)

- **whisper.cpp** — Speech-to-text at `./whisper.cpp/build/bin/whisper-cli`. Model and thread count configurable via `config.json` (`whisper_model`, `whisper_threads`). Defaults to `ggml-base.en.bin` with 3 threads. Benchmarked on a Pi 5: whisper pads every input to a 30s window, so transcription latency is fixed regardless of utterance length. `base.en` is the accuracy/speed sweet spot — `tiny.en` misrecognizes short questions outright, and `small.en` costs ~2x for no content gain. Threads scale 6.7s/3.5s/2.5s/2.5s at 1/2/3/4; the 4th thread buys ~40ms while starving the tkinter and audio-callback threads, so 3 is the cap.
- **Piper TTS** — Text-to-speech via the [`piper-tts`](https://github.com/OHF-Voice/piper1-gpl) Python package (installed into `.venv` from `pyproject.toml`). Voice `.onnx` + `.onnx.json` files live in `piper/`, downloaded by `python -m piper.download_voices --data-dir piper <voice-name>` during setup. The model is loaded once at agent startup via `PiperVoice.load()` and stays resident in-process — no subprocess, no separate server.
- **OpenWakeWord** — Wake word detection from `wakeword.onnx`

## Piper TTS

`PiperVoice.load()` is called once in `BotGUI.__init__` and the voice instance is reused for every utterance. `BotGUI.speak()` calls `self.piper_voice.synthesize(text)`, which yields streaming int16 PCM chunks; each chunk's `sample_rate` drives the playback `RawOutputStream` (resampled with `scipy.signal.resample` if the audio device doesn't natively support the voice's rate). Playback writes in 2048-sample sub-chunks and checks `self.interrupted` per sub-chunk so spacebar interrupts cut cleanly.

## Configuration

`.env` contains sensitive configuration (API keys). Copy `example.env` to `.env` and fill in your `ANTHROPIC_API_KEY`. It is loaded from `BASE_DIR`, is gitignored, and is kept at mode 0600 by the agent and by `setup.sh`.

`config.json` controls: Claude model name, voice model path, whisper model path, whisper thread count, audio energy threshold, chat memory toggle (`chat_memory`, memory.json only), transcript logging toggle (`log_transcripts`, agent.log only), camera rotation, a system prompt extension, microphone selection (`input_device` — index, name substring, or `null` for default), a preferred input sample rate (`input_sample_rate`), how many recent chat messages are resent to Claude each turn (`max_history_messages`, default 20), the recording `silence_threshold`, `wake_word_threshold` / `wake_word_consecutive`, `camera_trigger_words` (`[]` = camera never offered), `temperature` (0.0–1.0 or null; default null) and `effort` ("low"/"medium"/"high" or null; default "low"). The script merges user config over `DEFAULT_CONFIG` defaults after `validate_config()`: unknown keys are warned about and dropped; each value is type-checked against its default's type (or `NULLABLE_CONFIG_TYPES`) and range-checked (`CONFIG_RANGES`), and an invalid value is warned about and replaced by the default. All of these print `[CONFIG]` warnings. If `config.json` is not valid JSON (or not an object), the whole file is ignored with a loud error banner.

## Logging

All output goes through the `logging` module: logger `"bmo"` at INFO, root at WARNING (so library warnings are kept but httpx/anthropic INFO chatter is not). Handlers: stdout and `agent.log` in `BASE_DIR` via a `RotatingFileHandler` subclass (1 MB, `LOG_BACKUP_COUNT` = 3 backups, always mode 0600 because it holds transcripts). Lines carrying the user's or the bot's words (`Heard:`, `[PIPER SPEAKING]`, the web search query) go through `log_transcript()`: at INFO with the text when `log_transcripts` is true, otherwise still at INFO but logged as `<redacted, N chars>` (activity without content). `chat_memory` does not affect `agent.log`, and the memory wipe does not purge it. Use `log.info/warning/error/exception`, not `print`. When something fails (API errors, whisper, camera, a crashed main loop), the details and tracebacks are in `agent.log`.

## Display

**A desktop environment (X11/Wayland) is required.** The agent uses tkinter for its GUI, which needs a running display server. A headless/server-only Pi OS installation will fail with `couldn't connect to display ":0"`. If using Pi OS Lite, install `lightdm` and configure desktop autologin via `raspi-config`.

The target display is the Raspberry Pi's DSI touchscreen interface (800x480). The script sets `os.environ.setdefault("DISPLAY", ":0")` at the top of `agent.py` before any tkinter imports, ensuring the GUI renders to the DSI screen regardless of launch context (local terminal, SSH, or systemd service). Users can override by setting `DISPLAY` before running.

`setup.sh` installs a desktop autostart entry: it substitutes the repo path into `be-more-agent.desktop` and copies it to `~/.config/autostart/`, which launches `start_agent.sh` (execs `agent.py` via `.venv`) when the desktop session starts. Remove that file to disable autostart.

## Audio Handling

The agent auto-detects microphone/speaker sample rates and resamples on the fly (using scipy) to match hardware capabilities. This is critical for Pi hardware compatibility — Piper voices typically emit at 22050 Hz (read per-chunk from `chunk.sample_rate`) but many Pi audio devices only support 48000 Hz.

An audio energy gate (`_check_audio_energy`) checks RMS energy of recorded audio before invoking whisper.cpp. If the audio is below the configurable threshold (`audio_energy_threshold` in `config.json`, default `0.002`), transcription is skipped entirely, avoiding unnecessary CPU spikes on blank/silent recordings.
